## 1. 수업에서의 역할

- 사용 시점: 712 수업 16쪽 「달의 자원은 누구의 것일까」 (활동 3 · 세상과 이어 주는 과학)
- 한 판에 **7~8분**, 크롬북에서 학생 혼자 플레이
- 게임 뒤에 학습지 두 질문에 답합니다.
  1. 달 자원 개발로 생길 수 있는 문제점이나 갈등은?
  2. 달 자원을 평화적으로 분배하는 방안은?
- 따라서 게임 속 **이벤트 = 질문 1의 재료**, **엔딩에서 얻는 교훈 = 질문 2의 재료**가 되도록 만듭니다.
- 학습지 쓰기 부담을 줄이기 위해, 엔딩 화면에 "내가 겪은 갈등"과 "내가 고른 해결 방법"을 정리해서 보여 줍니다(학생은 보고 옮겨 적으면 됨).

배경 지식(슬라이드 내용)
- 여러 나라가 달을 탐사하는 까닭: 과학 연구, 우주 기지 건설, 그리고 백금·티타늄·희토류·헬륨(헬륨-3) 같은 자원
- 우주 조약: 어느 나라나 우주를 탐사할 수 있지만 **영토를 주장할 수는 없다**
- 2022년 8월 대한민국 최초의 달 궤도선 **다누리** 발사

## 3. 1단계 — 게임 본체

### 3-1. 캐릭터 (LPC)
- `docs/LPC-캐릭터-가이드.md`의 `lpc_build.py`로 만듭니다. 필요한 동작은 `walk`만 있으면 됩니다.
- **주인공**: 가이드 1절의 남학생 / 여학생 2종. 게임 시작 화면에서 둘 중 하나를 고릅니다. 이름은 포탈 닉네임(2단계) 또는 "탐사대장".
- **NPC 4명**: 가이드 5절 표를 참고해 머리·옷 색을 바꾼 조합으로 만듭니다(새 이름 짓기, 실제 국가명·실존 인물은 쓰지 않음).
  - 아르테 연합 대원 (파란 계열 옷)
  - 루나텍 기업 대표 (검은 정장)
  - 남방 신생국 대원 (초록 계열 옷)
  - 국제 달 협의회 의장 (회색 머리, 흰 옷)
- 규격과 그리기 규칙은 가이드 3·4절을 그대로 따릅니다: 64×64 칸, `imageSmoothingEnabled = false`, **정수 배율(2× 또는 3×)**, 좌표 정수 반올림, y값 큰 캐릭터를 나중에 그리기.
- NPC는 제자리 서 있기(0번 칸) + 주인공이 다가오면 주인공 쪽을 바라보게만 해도 충분합니다.

### 3-2. 맵
- 위에서 내려다보는 한 화면(스크롤 없음 또는 아주 조금) 크기의 달 표면.
- 바닥은 회색 달 표면 + 크레이터를 Canvas로 그려도 됩니다(사람 캐릭터가 아니므로 코드로 그려도 됨). 별이 보이는 검은 하늘 띠를 위쪽에 둡니다.
- 지점 5곳(다가가면 말풍선 아이콘 → 눌러서 이벤트):
  1. **우리 탐사대 기지** (다누리 궤도선 자원 지도로 세운 기지) (시작 지점, 주인공 기지)
  2. **헬륨-3 평원**
  3. **희토류 크레이터**
  4. **남극 얼음 지대**
  5. **국제 달 협의회 본부** (마지막 이벤트 장소, 다른 이벤트를 3개 이상 끝내야 열림)
- 지점 이름표는 한글로 화면에 표시합니다.

### 3-3. 조작 (크롬북 기준)
- 키보드: 방향키 / WASD 이동, Space·Enter로 대화·선택
- 마우스·터치: **누른 곳으로 걸어가기**(탭 이동). 화면 버튼식 방향 패드는 선택 사항.
- 선택지는 큰 버튼(최소 44px 높이), 1·2·3 숫자키로도 고를 수 있게.

### 3-4. 스탯 3개 (화면 위쪽 막대로 항상 표시)
| 스탯 | 뜻 | 시작값 |
|---|---|---|
| 💎 자원 | 우리 기지가 확보한 자원 | 30 |
| 🤝 국제 신뢰 | 다른 나라·기업이 우리를 믿는 정도 | 50 |
| 🕊️ 평화 | 달 전체가 평화로운 정도 | 50 |

(포탈은 이모지를 쓰지 않는 규칙이 있으니, 아이콘은 인라인 SVG 선 아이콘으로 그립니다. 위 표의 이모지는 설명용입니다.)
- 0~100 범위, 넘치거나 모자라면 잘라 냅니다.
- 선택하면 바뀐 값이 막대 옆에 `+10`, `-15`처럼 잠깐 떠오르게 합니다.

### 3-5. 이벤트 (7개, `rpg-moon-data.js`에 데이터로)
지점마다 이벤트가 있고, 각 이벤트는 **상황 설명 2~3문장 + 선택지 3개**입니다. 선택지마다 스탯 변화와 결과 한 줄, 그리고 엔딩에 정리될 `conflict`(갈등 이름)·`solution`(해결 방법 이름)을 가집니다.

아래는 초안입니다. 문구는 중학교 1학년이 읽기 쉽게 다듬어도 됩니다. 수치는 균형을 위해 조정해도 됩니다.

1. **[우리 탐사대 기지] 첫 보고**
   본부에서 "자원 탐사를 서둘러라"는 지시가 왔다. 대원들은 과학 연구도 하고 싶어 한다.
   - ① 자원 탐사에 모든 장비 투입 → 자원 +15, 평화 -5
   - ② 연구와 탐사를 반반 → 자원 +5, 신뢰 +5
   - ③ 연구 결과를 다른 나라와 공유하겠다고 발표 → 신뢰 +15, 자원 -5
   - conflict: "개발 목적을 둘러싼 갈등"

2. **[헬륨-3 평원] 먼저 꽂힌 깃발**
   아르테 연합 대원이 "이 평원은 우리 땅"이라며 깃발을 꽂아 두었다.
   - ① 깃발을 뽑고 채굴 시작 → 자원 +20, 신뢰 -20, 평화 -15
   - ② 우주 조약을 들어 "달은 누구의 영토도 아니다"라고 설명하고 함께 쓰자고 제안 → 신뢰 +10, 평화 +10, 자원 +5
   - ③ 다른 곳으로 이동 → 평화 +5, 자원 -5
   - conflict: "영토 주장 갈등", solution(②): "우주 조약 지키기"

3. **[희토류 크레이터] 기업의 독점**
   루나텍 기업 대표가 "돈을 많이 낸 나라에만 희토류를 팔겠다"고 한다.
   - ① 돈을 내고 독점 계약 → 자원 +20, 신뢰 -10, 평화 -10
   - ② 국제 공동 경매를 제안 → 신뢰 +10, 자원 +5
   - ③ 기술이 부족한 나라에도 일정량 나누도록 요구 → 평화 +15, 신뢰 +5, 자원 -5
   - conflict: "자원 독점", solution(③): "자원 나누기"

4. **[남극 얼음 지대] 물을 둘러싼 다툼**
   얼음(물)은 기지에서 마실 물, 산소, 연료가 된다. 세 나라가 같은 얼음층을 원한다.
   - ① 우리가 먼저 와서 차지 → 자원 +15, 평화 -15
   - ② 구역을 나누어 순서대로 쓰기 → 평화 +10, 신뢰 +5
   - ③ 공동 정수 시설을 함께 짓기 → 신뢰 +10, 평화 +10, 자원 -5
   - conflict: "물 자원 다툼", solution(③): "공동 시설 운영"

5. **[헬륨-3 평원 재방문 또는 아무 데서나 랜덤] 우주 쓰레기**
   채굴 장비 부품과 버려진 착륙선이 쌓여 탐사차가 고장 났다.
   - ① 그냥 두고 새 구역으로 이동 → 자원 +5, 평화 -10
   - ② 우리 쓰레기만 치우기 → 평화 +5, 자원 -5
   - ③ 쓰레기 처리 규칙을 함께 만들자고 제안 → 신뢰 +10, 평화 +10, 자원 -10
   - conflict: "환경 오염(우주 쓰레기)", solution(③): "환경 보호 규칙"

6. **[남방 신생국 대원] 소외된 나라**
   "우리는 로켓이 없어 달에 늦게 왔어요. 남은 자원이 없어요."
   - ① "먼저 온 사람이 임자"라고 거절 → 자원 +5, 신뢰 -15, 평화 -10
   - ② 우리 자원 일부를 나눠 줌 → 자원 -10, 신뢰 +15, 평화 +10
   - ③ 기술 교육을 약속 → 신뢰 +10, 평화 +5
   - conflict: "나라 사이의 격차", solution(②·③): "기술·자원 나누기"

7. **[국제 달 협의회 본부] 마지막 회의** (다른 이벤트 3개 이상 끝내야 열림)
   의장: "달 자원을 어떻게 나눌지 규칙을 정합시다."
   - ① 힘센 나라가 많이 갖는 규칙 → 자원 +15, 평화 -20
   - ② 국제법(협정)을 만들고 국제기구가 관리 → 평화 +15, 신뢰 +10
   - ③ 규칙 없이 각자 알아서 → 자원 +5, 평화 -10, 신뢰 -5
   - solution(②): "국제법과 국제기구 만들기"

### 3-6. 엔딩 4개 (마지막 회의 뒤 스탯으로 판정, 위에서부터 먼저 맞는 것)
| 엔딩 | 조건 | 한 줄 |
|---|---|---|
| **평화의 달** | 평화 ≥ 70 이고 신뢰 ≥ 60 | 여러 나라가 함께 쓰는 달 기지가 세워졌다. |
| **균형의 달** | 평화 ≥ 50 | 다툼도 있었지만 규칙을 만들어 함께 살아간다. |
| **독점의 달** | 자원 ≥ 70 이고 평화 < 50 | 우리 기지는 부자가 되었지만 다른 나라들의 원망을 샀다. |
| **분쟁의 달** | 그 밖 | 달에서 나라 사이의 다툼이 끊이지 않는다. |

엔딩 화면 구성
- 엔딩 이름, 그림(주인공 캐릭터 + 슬라이드의 `moonbase` 사진을 배경으로 써도 됨), 최종 스탯
- **"내가 겪은 갈등"**: 지나온 이벤트의 `conflict` 목록 → 학습지 질문 1
- **"내가 고른 평화적 해결 방법"**: 고른 선택지 중 `solution`이 있는 것 목록 (없으면 "다음엔 이런 방법도 있어요"로 ②번 해결책들을 보여 줌) → 학습지 질문 2
- 버튼: 「다시 하기」, 「게임 목록으로」

### 3-7. 시작 화면
- 제목 「다누리 탐사대장」, 부제 "달의 자원은 누구의 것일까?"
- 배경: 슬라이드의 `danuri` 사진(`lessons/712.html` 아래쪽 base64를 이미지 파일로 저장해서 `assets/img/rpg/`에 둠)
- 캐릭터 고르기(남학생·여학생) → 시작
- 오델로처럼 위 탭 [게임][규칙]. 규칙 탭에 조작법·스탯 3개 뜻·마지막 협의회 회의·보상만 짧게. 처음 온 기기는 규칙 탭부터(localStorage `rpg-moon-help-seen`). 화면에 "~해 보세요" 같은 채워 넣기용 안내 문구는 넣지 않습니다(포탈 규칙)

### 3-8. 크레딧
- 시작 화면 아래 「만든 이」 버튼 → 가이드 6절의 출처 문구 전체. NPC 조합을 바꿨다면 생성기의 Credits(TXT)를 받아 작가 목록을 맞춥니다.

## 4. 2단계 — 포탈 연결

### 4-1. 로그인
- `readLogin()`으로 토큰을 읽습니다. 로그인이 안 되어 있으면 `omok.html`처럼 "로그인하고 오세요" 안내를 보여 주되, **게임은 손님으로도 할 수 있게** 합니다(보상만 없음).
- 로그인 상태면 화면 위에 포탈 닉네임을 띄우고, 주인공 이름표에도 닉네임을 씁니다(닉네임은 아래 `moon_rpg_state`가 돌려줌. 승인 전이면 '닉네임 미정'). 학생 번호는 화면에 쓰지 않습니다.

### 4-2. 결과 저장 + 보상 (`supabase/patch_moon_rpg.sql`)
기존 `03_functions.sql`의 형식(주석 스타일, `security definer`, `set search_path = public`, `revoke all ... from public, anon, authenticated` 후 필요한 것만 `grant execute`)을 그대로 따릅니다.

```sql
-- 판 기록
create table if not exists public.moon_rpg_runs (
  id         bigint generated always as identity primary key,
  student_id uuid not null references public.students(id) on delete cascade,
  ending     text not null check (ending in ('peace','balance','monopoly','conflict')),
  stats      jsonb not null,     -- {"res":..,"trust":..,"peace":..}
  choices    jsonb not null,     -- [{"event":1,"pick":2}, ...]
  created_at timestamptz not null default now()
);

-- 설정: settings 표에 key='moon_rpg' (04_seed.sql 끝, 없는 값만 채움)
-- value: {"silver": 5}
```

**보상은 은화만** (포탈 결정 2026-10-29: 게임은 XP 없이 은화만). `point_events`에 `xp = 0, coins = 0, silver = settings.moon_rpg.silver`. 금화(coins)와 XP는 주지 않습니다. RLS는 켜고 교사만(02 끝), anon에는 표 정책을 주지 않습니다.

함수
1. `moon_rpg_state(p_token text) returns jsonb` (학생, anon 실행 가능): 닉네임, 보상 은화 수, 이미 받았는지(`rewarded`). 출입증이 없거나 틀리면 `{ok:false, error:'NO_SESSION'}` → 손님으로 플레이
2. `moon_rpg_finish(p_token text, p_ending text, p_stats jsonb, p_choices jsonb) returns jsonb` (학생, anon 실행 가능)
   - `_session_student(p_token)`이 없으면 `{ok:false, error:'NO_SESSION'}`
   - 기록 1줄 추가
   - **처음 끝까지 했을 때 한 번만** `point_events`에 `reason = '달 자원 RPG 완료'`, `silver = 설정값` (학생 줄을 잠가 두 번 눌러도 한 번만, 이미 받았으면 지급 없음). 엔딩 종류와 상관없이 같은 보상(좋은 엔딩만 보상하면 학생들이 정답 맞히기 게임처럼 함). 0번(선생님 계정)도 학생처럼 동작
   - 서버에서 `p_stats` 값 범위(0~100), `p_choices` 길이(최대 20), `p_ending`이 스탯 조건과 맞는지 한 번 더 확인(안 맞으면 `BAD_RUN`)
   - 결과: `{ok:true, rewarded: true/false, silver}`
3. `get_moon_rpg_class(p_class_id int) returns jsonb` (선생님만, `is_teacher()` 확인, 0번 제외)
   - 반별 엔딩 개수, 이벤트별 선택 비율
   - 수업 뒤 토론용("우리 반은 7번 회의에서 70%가 국제법을 골랐네")

### 4-3. 화면 연결
- 엔딩 화면에서 로그인 상태면 `moon_rpg_finish` 호출 → '+5은화' 또는 '보상은 이미 받았어요'. 버튼 하나에 요청 하나(누르는 즉시 잠금, 실패하면 [다시 보내기], 결과는 기기에 저장해 두었다가 연결되면 다시 보냄)

- `assets/js/whatsnew.js`의 `NEWS` 맨 위에 영어 한 줄 추가
- 다 만들면 `CLAUDE.md` 4절 폴더 구조, 5절 표, 6절 RPC 표, 맨 아래 '진행 상황'에 기록

## 5. 확인할 것 (완성 전에 직접 실행해서 보기)

- [ ] 크롬북 크기(1366×768)와 휴대폰 폭에서 화면이 잘리지 않음
- [ ] 캐릭터가 번지지 않고 또렷함(정수 배율, pixelated)
- [ ] 키보드·마우스 클릭·터치 세 가지로 끝까지 플레이 가능
- [ ] 한 판이 7~8분 안에 끝남(글 읽는 시간 포함)
- [ ] 네 엔딩이 모두 나올 수 있음(각 엔딩으로 가는 선택 경로를 하나씩 직접 해 보기)
- [ ] 엔딩 화면의 "갈등"·"해결 방법" 목록이 실제 고른 선택과 맞음
- [ ] 로그인 안 한 상태로도 게임이 됨(보상만 없음)
- [ ] 오목 스위치가 꺼진 반에서도 `rpg-moon.html`이 열림
- [ ] 보상은 은화만 들어가고 XP·금화는 그대로, 두 번 끝내도 한 번만 지급
- [ ] 저사양(`.lite`)에서도 끊기지 않음(캔버스는 움직일 때만 다시 그리기)
- [ ] 콘솔 오류 없음
- [ ] 크레딧 화면에 LPC 출처 문구가 있음
- [ ] SQL 파일은 만들었지만 **실행·배포는 하지 않음**
